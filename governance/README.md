# Blackpine Governance Framework

This directory defines the Phase 2 governance baseline used to organize Blackpine security controls and evidence.

## Status language

- **DEFINED** — the requirement or process is documented.
- **IMPLEMENTED** — the control has been configured or put into operation and there is evidence of that implementation.
- **OPERATING** — repeated evidence shows the control is being performed at its required cadence.
- **VERIFIED** — an appropriate independent review has tested the control or assurance claim.
- **OPEN** — the requirement has not yet reached the next required state.

A policy document by itself proves only that a requirement is **DEFINED**. It does not prove that the control is implemented, operating effectively, independently audited, or certified.

## Phase 2 files

- `CONTROL_REGISTER.md` — control objectives, ownership model, cadence, and required evidence.
- `EVIDENCE_REGISTER.md` — evidence structure and review rules.
- `INCIDENT_RESPONSE_STANDARD.md` — incident-response governance lifecycle.
- `DATA_HANDLING_STANDARD.md` — client-data minimization, access, transfer, retention, and deletion baseline.

## Publication boundary

This repository is public. It must not contain credentials, private keys, internal network details, customer data, incident evidence, confidential contracts, staff personal information, or security-sensitive recovery procedures. Operational evidence should be retained in an access-controlled evidence repository rather than committed here.

## Assurance boundary

These documents are preparation and governance artifacts. They are not ISO certification, a SOC report, legal advice, an audit opinion, or evidence that every listed control currently operates effectively.
