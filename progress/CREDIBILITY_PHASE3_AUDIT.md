# Credibility Refresh Phase 3 — Authority & Hard-to-Fake Evidence

## Scope

Phase 3 upgrades Blackpine's existing methodology, research library, sample assessment, engineering evidence and client-evidence controls into an explicit authority-evidence system.

## Public additions

- `/research/evidence/` — Authority & Evidence register.
- `/work/case-study-standard/` — client case-study release standard.
- Research navigation now exposes the authority register.
- Work navigation now exposes the case-study standard.

## Authority evidence model

Current Blackpine-owned inspectable evidence is classified as PUBLISHED:

- assessment methodology;
- fictional sample assessment;
- source-backed research/technical guidance library;
- engineering evidence;
- public browser-based tools;
- client testimonials and bounded outcome snapshots.

The following remain OPEN and are not claimed as earned recognition:

- original measurement/dataset research portfolio;
- CVE attribution;
- vendor acknowledgement / hall-of-fame recognition;
- conference, podcast or media appearance;
- external technical byline;
- full client case study.

## Framework/source verification

Authoritative references were checked on 2026-10-24 and recorded in both machine-readable site data and `governance/REFERENCE_SOURCE_REGISTER.md`:

- NIST Cybersecurity Framework 2.0;
- CIS Critical Security Controls v8.1;
- OWASP Top 10 2025;
- OWASP ASVS 5.0.0;
- MITRE ATT&CK v20.0.

Framework use is reference/mapping context only and is not represented as certification.

## Research evidence boundary

All current published research entries must retain article-level sources. The current library is classified as source-backed technical guidance/engineering analysis rather than an original measurement or vulnerability-research portfolio. Original Research has a separate evidence gate requiring a defined research question, Blackpine-collected dataset/experiment/measurement method, collection scope/dates, exclusions/bias, analysis, limitations, reproducibility information and disclosure review.

## Client case-study boundary

Current supplied client evidence supports:

- 20 testimonials;
- 3 testimonial-derived evidence snapshots;
- 0 full anonymized client case studies under the Phase 3 release gate.

A full case study requires publication basis, safe organization description, actual problem, actual scope, approved material evidence, action actually taken, evidence-supported result and final confidentiality/source review. Missing facts must not be inferred.

## Automated release gates

Phase 3 adds checks for:

- current framework/reference versions and authoritative HTTPS sources;
- six current PUBLISHED evidence classes;
- six recognition classes remaining OPEN;
- exact authority IDs shared by site data and governance records;
- sources present for every current research publication;
- research publication ledger completeness;
- current framework wording in public methodology;
- no stale CIS Controls v8 wording;
- explicit zero-full-case-study boundary;
- no testimonial-to-case-study inflation;
- existing privacy, security, claims, hosting, external-link, accessibility, browser and performance gates.
