# Credibility Refresh Phase 3 Plan

Phase 3 turns Blackpine's existing methodology, research library, sample report, engineering evidence and client-evidence controls into a harder-to-fake authority system.

1. Add a public Authority & Evidence page that separates current inspectable evidence from future/earned recognition.
2. Add a framework/source register using current authoritative references and explicit last-verified dates rather than vague framework-name dropping.
3. Add a public research-evidence ledger showing publication class, evidence basis and whether a publication is Blackpine-original measurement/research or guidance based on external sources.
4. Add a case-study publication gate and public readiness explanation; do not invent full client case studies from testimonials.
5. Add explicit status controls for CVEs, vendor acknowledgements, conference/media appearances, external bylines and public tools so absent evidence stays OPEN rather than becoming marketing copy.
6. Strengthen research publication metadata and citation expectations without misrepresenting existing guides as original datasets or vulnerability research.
7. Add automated regression checks for framework version drift, evidence-class wording, case-study boundaries and unsupported authority claims.
8. Preserve all existing privacy, claims, hosting, browser, external-link, accessibility and performance gates.
9. Run the full static/core audit, external-destination audit and rendered Chrome/Firefox audit on the exact final head before merge.
10. Merge only after all release gates pass, then re-check `main` and deployment.
